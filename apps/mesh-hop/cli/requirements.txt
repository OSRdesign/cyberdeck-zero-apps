# The meshcore-cli bundle of Mesh Hop's CLI page (report 033, packaging K1): exact pins, one sha256 per accepted file.
# cli/vendor.sh fetches them with  pip download --require-hashes --no-deps --only-binary=:all:  for each package
# architecture (arm64: manylinux2014_aarch64, amd64: manylinux2014_x86_64; CPython >= 3.10, abi3) and unpacks them into
# root/opt/mesh-hop/cli/py (arm64) and root.amd64/opt/mesh-hop/cli/py (what differs on amd64: pycryptodome's .so files).
# Every wheel is pure Python (py3-none-any) except pycryptodome (cp39-abi3: one build for every CPython 3 >= 3.9).
# Bump deliberately: change a pin and its hashes (https://pypi.org/pypi/<name>/<version>/json), run build.sh cli (the
# smoke flow), note the bump in the README.
#
# Not bundled, and why:
#   bleak, dbus-fast    Bluetooth LE in Python: never used, meshcore-cli reaches the node through Mesh Hop's TCP relay;
#                       both upstream imports are guarded (meshcore_cli.py:28-33, meshcore/ble_cx.py:11-21), and
#                       mccli.py blocks bleak so a system copy is not loaded either
#   requests            imported at start, used only by upload_card / upload_contact: the Debian package
#                       python3-requests (depends; keeps certifi, MPL-2.0, out of this package)
#   pyserial            imported at start (serial.tools.list_ports; serial_asyncio_fast needs it), unused on the TCP
#                       relay: the Debian package python3-serial (depends), the same 3.5 as PyPI's last release, whose
#                       wheel carries no licence file
#   async-timeout, typing-extensions   bleak's backports for Python < 3.11 / 3.12
